# S3

<HideInUI>

Use this guide to set up the [S3](https://docs.aws.amazon.com) source connector and find reference information.

</HideInUI>

:::warning
Cloud storage may incur egress costs. Egress means transferring data out of cloud storage, such as downloading files or accessing them elsewhere. For detailed information about egress costs, see the [AWS S3 pricing guide](https://aws.amazon.com/s3/pricing/).
:::

## Prerequisites

- Access to the S3 bucket containing the files you want to replicate.
- For **private buckets**, an AWS account that can grant permission to read from the bucket.

## Setup guide

### Step 1: Set up S3

Choose authentication from the **Authentication** dropdown when setting up the connector: **IAM User**, **IAM Role** or **No Authentication**. For a private bucket, create a policy with the required permissions:

#### Create a policy

1. Sign in to your Amazon AWS account and open the [IAM console](https://console.aws.amazon.com/iam/home#home).
2. In the IAM dashboard, select **Policies**, then click **Create Policy**.
3. Select the **JSON** tab, then paste the following JSON into the Policy editor. Replace the bucket name with yours:

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
        "Effect": "Allow",
        "Action": [
                "s3:GetObject",
                "s3:ListBucket"
        ],
        "Resource": [
                "arn:aws:s3:::{your-bucket-name}/*",
                "arn:aws:s3:::{your-bucket-name}"
        ]
        }
    ]
}
```

:::note
Object-level permissions alone can't authenticate the connection. Include the **bucket-level** permissions shown in the example above.
:::

4. Give your policy a descriptive name, then click **Create policy**.

#### Option 1: Use an IAM User

1. In the IAM dashboard, click **Users**. Select an existing IAM user or click **Add users** to create one.
2. For an _existing_ IAM user, open the **Add permissions** dropdown menu and select **Add permissions**. For a _new_ user, selecting a name takes you to the Permissions screen.
3. Select **Attach policies directly**, then find and select your new policy. Click **Next**, then **Add permissions**.
4. After creating your user, select the **Security credentials** tab and click **Create access key**. Select a use case and add optional tags to your access key. Click **Create access key** to generate the keys.

:::caution
Your `Secret Access Key` appears only once when created. Copy it and store it securely for future use.
:::

For more information about managing your access keys, see the
[official AWS documentation](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html).

### Step 2: Set up the S3 connector in Airbyte

### Airbyte Cloud

1. [Log into your Airbyte Cloud](https://cloud.airbyte.com/workspaces) account.
2. Click Sources, then click + New source.
3. On the Set up the source page, select S3 from the Source type dropdown.
4. Enter a name for the S3 connector.
5. Enter the name of the **Bucket** containing the files you want to replicate.
6. Choose an authentication method from the **Authentication** dropdown:
   - **IAM User**: Enter the AWS Access Key ID and AWS Secret Access Key.
   - **IAM Role**: Enter the AWS Role ARN.
   - **No Authentication / Default AWS Credentials**: Use this for public buckets or the default AWS credential chain (instance profile, IRSA, or environment variables).
7. (Optional) Choose a [delivery method](../../platform/using-airbyte/delivery-methods) for your data. You can find this option under **Advanced**.
8. Add a stream:
   1. Give the stream a **Name**.
   2. In the **Format** box, use the dropdown menu to select the format of the files you want to replicate. Supported formats are **CSV**, **Parquet**, **Avro** and **JSONL**. Enable **Optional fields** in the **Format** box to enter more settings for the selected format. For details about these settings, see the [File Format section](#file-format-settings) below.
   3. (Optional) Enter the **Globs**, which determines which files are synced. This regular expression lets Airbyte match the specific files you want to replicate. To replicate every file in your bucket, use `**` as the pattern. For more precise matching options, see the [Globs section](#globs) below.
   4. (Optional) Change the **Days To Sync If History Is Full** value. This controls the lookback window used to determine which files to sync when the state history is full. See the [State section](#state) below for details.
   5. (Optional) To enforce a specific schema, enter an **Input schema**. By default, this value is `{}` and infers the schema from the file\(s\) you're replicating. For details about providing a custom schema, see the [User Schema section](#user-schema).
   6. (Optional) Select **Schemaless** to skip all record validation against a schema. When selected, the schema is `{"data": "object"}` and all downstream data is nested in a "data" field. This option suits records whose schema changes frequently.
   7. (Optional) Select a **Validation Policy** to control how Airbyte handles records that don't match the schema. You can emit the record anyway, but fields absent from the schema may not reach the destination. Alternatively, skip the record or wait for the next discovery, which occurs within 24 hours.

You can leave other optional fields empty. See the [S3 Provider Settings section](#s3-provider-settings) below for more information about each field.

## Globs

\(In short: path pattern syntax using [wcmatch.glob](https://facelessuser.github.io/wcmatch/glob/). GLOBSTAR and SPLIT flags are enabled.\)

Use glob-style patterns to sync multiple files without specifying every file path. This lets you:

- Reference many files with one pattern. For example, `**` indicates every file in the bucket.
- Reference future files that don't exist yet \(and therefore don't have a specific path\).

You must provide a path pattern. For complex directory layouts, you can provide multiple patterns separated by \|.

Each path pattern starts from the bucket's _root_. Don't include the bucket name in the pattern\(s\).

Example patterns:

- `**`: Match everything.
- `**/*.csv`: Match all files with a specific extension.
- `myFolder/**/*.csv`: Match all csv files anywhere under myFolder.
- `*/**`: Match everything at least one folder deep.
- `*/*/*/**`: Match everything at least three folders deep.
- `**/file.*|**/file`: Match every file named "file" with any extension \(or no extension\).
- `x/*/y/*`: Match all files in folder x -&gt; any folder -&gt; folder y.
- `**/prefix*.csv`: Match all csv files with a specific prefix.
- `**/prefix*.parquet`: Match all parquet files with a specific prefix.

Consider this specific example, which matches the following bucket layout:

```text
myBucket
    -> log_files
    -> some_table_files
        -> part1.csv
        -> part2.csv
    -> images
    -> more_table_files
        -> part3.csv
    -> extras
        -> misc
            -> another_part1.csv
```

You want part1.csv, part2.csv and part3.csv, while excluding another_part1.csv for now. You can do this in several ways:

- Use the single pattern `**/part*.csv` to select every csv file named "partX".
- For tighter matching, use the dual pattern `some_table_files/*.csv|more_table_files/*.csv` to select relevant files only from those exact folders.
- Use `*table_files/*.csv` to achieve the same result with one pattern. However, unexpected new folders could cause future problems.
- You can also use recursive wildcards. The pattern `extras/**/*.csv` selects csv files nested below "extras", including "extras/misc/another_part1.csv".

Path patterns offer several ways to reach the same result. Choose a clear pattern that can accommodate future directory changes.

## State

For incremental syncs, Airbyte syncs files from oldest to newest. Each synced file, up to 10,000, becomes an entry in the connection state message's "history" section.
When history is full, older messages are removed. Airbyte then reads files modified within `Days to Sync if History is Full` days before the newest file's date in history.

## User schema

Provide a schema for more control over this stream's output. Without one, Airbyte infers columns and datatypes from the first created file matching your path pattern and suffix. This approach will suit most cases. However, you may want to enforce a schema when:

:::note

Without a schema for a CSV file, Airbyte infers every column as a `string`.

:::

- You only need a known subset of columns. Other columns remain included but are packed into the `_ab_additional_properties` map.
- Your initial dataset has few records, so its automatic type inference may not represent future data.
- You want to define types for every column deliberately.
- You know which columns future data will add. Include them as core schema columns instead of placing them in the `_ab_additional_properties` map.

You may have another reason. Provide the schema as valid JSON using a map of `{"column": "datatype"}`. Each datatype must be one of:

- string
- number
- integer
- object
- array
- boolean
- null

For example:

- `{"id": "integer", "location": "string", "longitude": "number", "latitude": "number"}`
- `{"username": "string", "friends": "array", "information": "object"}`

:::note

The S3 Source connector previously inferred schemas from every available file, then merged them into a superset schema. From version 2.0.0, schema inference uses only the first file found. The first file considered is the oldest one written to the prefix.

:::

## S3 provider settings

- **Authentication**: Select **IAM User** to provide an [AWS Access Key ID and AWS Secret Access Key](https://docs.aws.amazon.com/general/latest/gr/aws-sec-cred-types.html#access-keys-and-secret-access-keys) for a private bucket. Select **IAM Role** to provide an AWS Role ARN. Select **No Authentication / Default AWS Credentials** for public buckets or the default AWS credential chain.
- **Endpoint**: This optional parameter enables non-Amazon S3 compatible services. Leave this field blank when using the default Amazon service.
- **Start Date**: This optional parameter sets a UTC start date and time for data replication. Files _not_ modified since this date and time won't be replicated. Use the provided datepicker (recommended) or enter the date programmatically in the format `YYYY-MM-DDTHH:mm:ssZ`. Leave this field blank to replicate every file not excluded by **Path Pattern** and **Path Prefix**.

## File format settings

### CSV

CSV files are plain text, so specific reader options are often required for correct parsing. Apply these settings consistently whenever you create or export a CSV.

- **Header Definition**: Controls how headers are defined. `User Provided` assumes the CSV has no header row and uses the provided headers. `Autogenerated` also assumes no header row. The CDK generates headers using `f{i}`, where `i` is the zero-based index. Otherwise, the CSV file's header is used by default. To generate or provide column names for a CSV with headers, set "Skip rows before header" to ignore the header row.
- **Delimiter**: CSV means Comma Separated Values, but the term also covers flat-file data separated by other characters. Use the delimiter field to specify the separator character. To use [tab-delimiters](https://en.wikipedia.org/wiki/Tab-separated_values), set this value to `\t`. The default value is `,`.
- **Double Quote**: Determines whether two quotes within a quoted CSV value represent one quote in the data. The default is True.
- **Encoding**: Some data uses a different character set, typically for different alphabets. See the [list of allowable encodings here](https://docs.python.org/3/library/codecs.html#standard-encodings). The default is `utf8`.
- **Escape Character**: An escape character can prefix a reserved character to ensure correct parsing. A common choice is the backslash (`\`). For example, consider the following data:

```
Product,Description,Price
Jeans,"Navy Blue, Bootcut, 34\"",49.99
```

The backslash (`\`) directly precedes the second double quote (`"`). This shows that it isn't the field's closing quote. Instead, it's a literal double quote included in the value, showing the jeans size in inches: `34"`.

Leave this field blank, the default option, to disable escaping.

- **False Values**: A set of case-sensitive strings interpreted as false values.
- **Null Values**: A set of case-sensitive strings interpreted as null values. To interpret 'NA' as null, enter 'NA' in this field.
- **Quote Character**: Data values may contain reserved characters, such as a comma used as the delimiter. CSVs handle these values by wrapping them in defined quote characters, allowing correct parsing. The default is `"`.
- **Skip Rows After Header**: The number of rows skipped after the header row.
- **Skip Rows Before Header**: The number of rows skipped before the header row.
- **Strings Can Be Null**: Controls whether strings can be interpreted as null values. If true, strings matching the null_values set are interpreted as null. If false, they're interpreted as the strings themselves.
- **True Values**: A set of case-sensitive strings interpreted as true values.

### Parquet

Apache Parquet is a column-oriented data storage format in the Apache Hadoop ecosystem. It offers efficient compression and encoding for handling complex data in bulk. Partitioned parquet datasets aren't currently supported. These settings are available:

- **Convert Decimal Fields to Floats**: Controls whether decimal fields are converted to floats. This conversion loses precision, so it isn't recommended.

### Avro

The Avro parser uses the [Fastavro library](https://fastavro.readthedocs.io/en/latest/). These settings are available:

- **Convert Double Fields to Strings**: Controls whether double fields are converted to strings. This is recommended for highly precise decimal numbers because floating-point handling can lose precision.

### JSONL

### Document File Type Format

The Document File Type Format extracts text from Markdown, TXT, PDF, Word and Powerpoint documents. When selected, the connector outputs the extracted text in one field named `content`. The `document_key` field stores a unique identifier for the processed file, which can serve as a primary key. The document content includes markdown formatting converted from the original format. Each file matching the glob pattern must be markdown (`md`), PDF (`pdf`), Word (`docx`) or Powerpoint (`.pptx`).

Each document produces one record. Large files can produce large records that don't fit every destination. Each destination has different limits for string fields.

#### Parse with the Unstructured.io Python Library

This connector uses the open source [Unstructured](https://unstructured-io.github.io/unstructured/introduction.html#product-offerings) library for OCR and text extraction. It extracts from PDFs, MS Word files, embedded tables and images. Read about the parsing logic in the [Unstructured docs](https://unstructured-io.github.io/unstructured/core/partition.html). Learn about other Unstructured tools and services at [www.unstructured.io](https://www.unstructured.io).

## Troubleshoot the connection test

Enter only the bucket name in **Bucket**. A pasted `s3://bucket` or
`https://bucket.s3.amazonaws.com` is accepted and normalised to `bucket`.
URLs containing a path are rejected, rather than having their path silently ignored.
Move the path into the stream glob or path prefix to avoid reading unintended files.

The connection test identifies invalid access key IDs, signatures, missing buckets and unreachable endpoints. Follow the error to check the access key ID, secret access key, bucket name, region, endpoint URL or network allowlist.
For access denied errors, grant the configured IAM user or role `s3:ListBucket` on the bucket. Grant `s3:GetObject` on its objects, then check the bucket policy.

A stream without matching files fails the connection test. Compare its globs and path prefix with the bucket's object keys. If a file is found but can't be parsed, check its contents against the selected format, encoding and stream format options.
The optional **Skip Full Check for Parquet** setting still skips record parsing.
